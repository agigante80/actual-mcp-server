**Phase 1: Server & Read-Only (9 operations):**

- get_context, topic: "server"
  Input: { topic: "server" }
  Expect: server metadata object (MCP server version, name, Node.js and SDK versions, tool count, uptime), no error

- get_context, topic: "version"
  Input: { topic: "version" }
  Expect: { version: string } on success OR { error: string } on version mismatch: both are ✓ non-failures; only an exception counts as ✗ failure

- list_entities, type: "account"
  Input: { type: "account" }
  Expect: array (possibly empty), no error
  Save the first account's name and id as `{account1_name}` and `{account1_id}` for use in the name lookup below

- list_entities, type: "category_group"
  Input: { type: "category_group" }
  Expect: category groups array, no error

- list_entities, type: "category"
  Input: { type: "category" }
  Expect: categories array (grouped or flat per API contract), no error
  Save the first category's name as `{cat1_name}`

- list_entities, type: "payee"
  Input: { type: "payee" }
  Expect: payees array (possibly empty), no error
  Save the first non-transfer payee's name as `{payee1_name}`

- get_context, topic: "structure" (positive + negative sub-calls, counts as 1 operation):
  Positive: call with { topic: "structure" } (or no topic at all: structure is the default).
    Expect: { accounts: [...], categoryGroups: [...], payees: [...], payeesTruncated: boolean, payeeTotal: number }
    Verify: accounts, categoryGroups, and payees are arrays; no error thrown (✓ pass).
  Negative: call with { topic: "structure", payee_limit: 0 }.
    Expect: validation error naming payee_limit (must be >= 1) (✓ pass).

- list_entities name lookup, type: "account" (resolves one exact name to its id; 4 sub-calls count as 1 operation).
  Test all 4 supported types:
  * list_entities, type: "account": Input { type: "account", name: "{account1_name}" } → verify returned id matches `{account1_id}`
  * list_entities, type: "category": Input { type: "category", name: "{cat1_name}" } → verify returned id is a UUID
  * list_entities, type: "payee": Input { type: "payee", name: "{payee1_name}" } → verify returned id is a UUID
  * list_entities, type: "schedule": Input { type: "schedule", name: "<any schedule name>" }; if no schedules exist, report as ✓ informational (expected for most test budgets)

- list_entities query search, type: "payee" (positive + negative sub-calls, counts as 1 operation):
  Positive: use `{payee1_name}` saved above.
    Take a 3-to-5 character substring from the middle of the name as the search query.
    Input: { type: "payee", query: "<substring>", match_type: "contains", limit: 20 }
    Expect: { matches: [...], count: N, type: 'payees', matchType: 'contains' } with N >= 1
    Verify: at least one entry in matches has the same id as the payee whose name was used.
    If no named payees exist in the budget, report as ✓ informational and skip this sub-call.
  Negative (no-match contract):
    Input: { type: "payee", query: "zzz-nonexistent-xqz-9999", match_type: "contains", limit: 10 }
    Expect: { matches: [], count: 0 } with no error field and no exception thrown.
    Verify: count === 0, matches is an empty array.
